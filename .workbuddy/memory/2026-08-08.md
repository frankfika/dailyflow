## DailyFlow 思维导图与 Tasks 工作流重构 — 审计阶段

用户要求接管 DailyFlow 的思维导图与 Tasks 工作流重构项目。本轮要求：
1. 先分析现状（不修改代码）
2. 给出产品工作流理解、证据化问题清单、数据模型、实施计划、待确认决策

### 已审计的关键文件
- 前端：`src/components/MindMap/MindMapView.tsx`、`MindMapCanvas.tsx`、`MindMapNode.tsx`、`NodeContextMenu.tsx`、`src/hooks/useMindMapActions.ts`、`src/api/client.ts`、`src/App.tsx`
- 后端：`server/routes/mindmaps.ts`、`server/routes/tasks.ts`、`server/services/mindmaps.ts`、`server/services/topicSpaces.ts`、`server/services/taskMetadata.ts`、`server/services/parser.ts`
- 类型：`server/types/mindmap.ts`、`server/types/task.ts`、`server/types/topicSpace.ts`

### 已确认的关键证据
1. **任务状态同步只在今日生效** — `MindMapView` 的镜像 effect 依赖 `linkableTasks`，而该列表由 App.tsx 从 `tasks`（今日日期的任务）派生，跨日期任务不在其中。
2. **Topic Space 任务列表是单日期过滤** — `tasksInActiveSpace` 在 App.tsx 直接过滤今日 `tasks`，注释明确承认这是 Phase 2 简化，未跨日期。
3. **解除关联存在契约不一致** — 前端 `tasksApi.updateSpace(taskId, null)` 不传 date；服务端 `PUT /api/tasks/:taskId/space` 却强制 `date` required 并据此读文件改 `^space:` 标记。客户端调用一定会 400 或找不到任务。
4. **节点改标题不回写 Task** — `MindMapCanvas.onCommitEdit` 只改 map 节点 text，不触发任务更新接口。
5. **节点状态变化不回写 Task** — `onCycleStatus` 只改节点 status，不调 task PATCH。
6. **删除路径未处理孤儿** — 删节点（canvas onDelete）只删 map 节点；删 Task（tasks.ts DELETE）不通知 map 清 taskId。
7. **缺少 planOrder 字段** — `MindMapNode` 和 `MindMap` 类型都没有 `planOrder`，排序仅靠 nodes 数组顺序隐含。
8. **进度统计把所有非根当任务** — MindMapView 的 `progress` 把除根以外所有节点计入 total，不分 kind。
9. **没有沉浸模式** — App.tsx 的 mindmap 容器被主侧栏、TopicTabs、view switcher、TagFilterRow 包裹；MindMapView 内部还有 MindMapList 左栏和 header。
10. **"设为任务"隐藏在右键菜单** — 只有 `NodeContextMenu` 触发 promote/link，不支持多选批量。
11. **缩放/平移配置** — MindMapCanvas 已设 `zoomOnScroll`、`panOnDrag`、`panOnScroll={false}`、`minZoom 0.1 / maxZoom 2`，但未配置 `zoomOnPinch`、`zoomOnDoubleClick`、指针位置缩放等沉浸手势。

### 结论
本轮只产出审计与计划文档，等待用户确认后再分阶段实施。
