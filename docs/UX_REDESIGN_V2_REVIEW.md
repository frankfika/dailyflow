# DailyFlow UX_REDESIGN_V2 整体 Review（独立视角）

> 审阅对象：`docs/UX_REDESIGN_V2.md`（v2，用户路径版）
> 审阅方式：对照现有代码（App.tsx / Sidebar / TodayBacklog / TaskCard / SettingsModal / events / v2 features）+ 对照 README 核心功能清单 + 对照设计原则自查
> 结论：**方向正确（用户路径优先），但存在 4 个必须修正的 P0 问题、5 个 P1 问题、1 个文档问题。修正后可以实施。**

---

## 一、肯定：这版做对了什么

1. **用户路径优先**（P1-P5）是对的方向——用户感受的是"我在做事"，不是"我选功能"。
2. **任务行点开 → 行内展开**（P2.2）是 Things/Linear 正确模式，也是"功能融入不砍功能"的正确落地方式。
3. **底部固定输入框**正确，2 秒加任务。
4. **Events / Mind Map / Harness / AI 推进 100% 保留**，且 Context 预览弹层把"确认前 0 写入"变成可见承诺——这条修复了 v0.2 的问题。
5. **画布 ↔ 今日双向桥接**（P3.8 + P2.2）闭环成立：任务 → 转项目 → 画布 → 节点 → 添加为任务 → 回今日。

## 二、P0 问题（必须修正，否则不能实施）

### P0-1 "永远在主页"原则与 Events 独立页自相矛盾

- 原则 3 写"切换的不是页面，是展开/收起"；
- 但 P3.2 又写"Events 全屏独立路由"、"进得少但进得深"。

**这是两个页面，不是"永远在主页"**。诚实地说，这个设计是**"两页模型"：主页（Today）+ Events 深度页**。宣传可以叫"单页优先"，但架构必须承认两页。否则实施时会在"Events 算不算页面"上反复打架。

**修正**：把原则 3 改成——
> "主页是默认的、永久的家；Events 是唯一例外——深度工作画布作为第二页存在；其余一切（笔记/AI/日历/记忆/设置）都是浮层。"

### P0-2 P1.1 默认态把"焦点 3 件"和"主动建议"弄没了

对照 README（这是产品核心卖点）：
- "支持手动选择今日重点，也支持 AI 根据时间、精力和约束提出计划"（**焦点/Commitment**）
- Sprint 1 P0：**主动提案**（逾期 5 天自动建议排进今天）

但 v2 的 P1.1 默认态只有：标题 + 任务列表 + 已完成折叠 + 输入框。**没有"焦点 3 件"，没有"主动建议 banner"**。

这正是你两次批评我的毛病第三次重演："功能很好的融入，而不是说就搞没了。" v2 又悄悄把两个核心区块从主页删了。

**修正**：P1.1 恢复这两个区块，但极简化：
```
2026 年 8 月 31 日 周一                                    ⌘K
─────────────────────────────────────────────────────────────
🤖 建议：保密协议已逾期 5 天   [排进今天] [忽略]        ← 主动建议（1 行）
─────────────────────────────────────────────────────────────
今天 · 焦点 3 件                               [选 3 件 →]   ← 焦点（默认折叠成一行）
─────────────────────────────────────────────────────────────
☐ 完成 DSH 接入测试
...
```

### P0-3 日历 / 记忆 / 团队 只留了 ⌘K 命令，界面又没了

对照 v0.4 的 44 项清单，v2 里这三个功能**只剩一行命令**：
- `⌘5 日历`——没有日历浮层 wireframe（v0.4 有完整日/周/月视图 + 飞书连接）
- `⌘6 搜记忆`——没有 Memory 3 层搜索 wireframe（v0.4 有完整的结构化/元数据/全文命中展示）
- `⌘7 团队`——完全没有任何界面（TeamView 是 v1.9 上线的功能，有 leader 只读 + git 时间线）

**这不是"融入"，是又一次"藏没了"。** 用户需要看"今天下午有会吗"（日历是高频查询）、需要搜"这件事我之前处理过吗"（记忆）。

**修正**：至少给日历和记忆各补一张浮层 wireframe（参考 v0.4 的 4.5 / 8 节），团队给一行说明（保留 TeamView 现状，仅入口移入 ⌘K）。

### P0-4 新手可发现性：原则 4 自相矛盾

原则 4 说"新手用户看按钮也能用"，但设计里所有功能都藏在 ⌘K：
- 侧边栏砍了
- 顶栏只有一个 ⌘K 图标
- 新手不知道 ⌘K 的存在 → 不知道笔记、日历、AI、事件在哪 → **功能对新手真的消失了**

Linear/Things 敢这么干，是因为它们是"键盘优先"的老牌工具、用户是高手；DailyFlow 是带 onboarding 的普通桌面应用，用户不是。

**修正（二选一）**：
1. 主页保持一个可见的"入口提示"：顶栏 ⌘K 图标旁显示"⌘K"文字（而非只有图标）；首次启动（onboarding）教 3 个键：⌘K / ⌘N / 回车。
2. 或者保留 60px 图标栏（不砍到 0）：今日 / 事件 / 笔记 / AI 四个图标常驻，⌘K 管其余。这也是"极简"。

推荐方案 2——它同时解决"砍侧边栏"的争议，且和 P0-1 的"两页模型"天然匹配。

## 三、P1 问题（重要，可分批处理）

### P1-1 ⌘K 成了新的"侧边栏"：高频和低频没有区分

⌘K 塞了：跳今天 / 进事件 / AI 脑暴 / 复盘 / 整理遗留 / 日历 / 记忆 / 团队 / 设置 / 切上下文 / 切工作区 / 历史日期 / 检查更新 / AI 深度对话。

其中"日历"是**高频查询**（"今天下午有会吗"），每次都要 ⌘K → 选 → esc 关闭，一天 10 次会烦死。Linear 的 ⌘K 主要做**搜索跳转**，日历/设置是常驻入口。

**修正**：⌘K 按"搜索跳转"和"管理命令"分层；日历/记忆这类高频查询给一个**主页可触达的入口**（比如 P1.1 的 ⌘K 图标点击展开的就是"快速面板"：日历摘要 1 行 + 搜索框 + 最近）。

### P1-2 "AI 帮你做"是新增功能，设计没有标注，且 `?` 有输入法问题

- P4.1 AI 脑暴、P4.2 AI 拆解/改写/转项目：现有代码只有 `processBrainDump`（AI 提取任务）和 AI 推进（Event Operator）。**"AI 拆解成子任务""AI 改写""AI 转项目"都是新后端逻辑**，设计把它们画得像现有能力，实施时会被低估。
- P4.3 用 `?` 前缀进 AI 模式：中文输入法下用户会打 `？`（全角），需要处理 IME；且 Slack 的 `/` 是更成熟的约定。

**修正**：在设计里标注"✅ 已有 / 🆕 新增"；`?` 前缀改成 `/ask` 或同时接受全角 `？`。

### P1-3 设置"高级"tab 又变成杂货袋

4 tab（日常/AI/同步/高级），但"高级"里塞了：主动建议 / 自动检查更新 / 隐私面板 / 更新通道 / 调试模式。这正是我们批评 7 tab 的原因——"高级"变回垃圾桶。

**修正**：**隐私面板**值得独立可见（0 字节上传是产品卖点，README 单列一章）——把它从"高级"提到独立 tab 或"日常"可见位置；"高级"只留调试类。

### P1-4 17:30 自动弹复盘是打断式反模式

P5.1 "每天 17:30 自动浮起"：用户在专注时会突然被打断。而且项目**已有防打扰机制**（Proactive Proposal 的全局开关/静默时段/每周最多 3 次），v2 设计完全没沿用。

**修正**：默认不自动弹。改成：17:30 时在主页顶部显示一条**安静的提示条**（"今天收尾？[写复盘]"），可点可忽略可关；或仅在"今日完成 ≥ 3 件"时提示。

### P1-5 实施顺序没有风险标注

- 步骤 1"主页极简化"：实际要动 TodayBacklog / TaskCard / TodayScopeTabs / App.tsx 的 props，涉及现有组件测试。
- 步骤 9"砍侧边栏"：**会直接破坏 `e2e/sidebar-viewports.spec.ts`（3 个用例）和 Sidebar 单测**——现在代码里 Sidebar 有 643 行，Viewport 逻辑（mobile/tablet/desktop + hover-expand + ResizeHandle）是精心做的。
- 步骤 4"⌘K"：**现有代码没有 CommandPalette 组件，是全新功能**（已验证 `grep cmd-k` 无结果），不是"加个入口"。

**修正**：每步标注"涉及文件 / 会挂的测试 / 回滚方式"。

## 五、修正后的设计决策（汇总）

| # | 决策 | 修正后 |
|---|---|---|
| 1 | 页面模型 | **两页模型**：主页（Today）+ Events 深度页；其余全部浮层 |
| 2 | 主页默认态 | 日期 + 主动建议（1 行）+ 焦点 3 件（折叠一行）+ 任务 + 已完成 + 底部输入框 |
| 3 | 导航 | **保留 60px 图标栏**（今日/事件/笔记/AI + ⌘K），不砍到 0 |
| 4 | ⌘K | 分层：搜索跳转 / 管理命令；高频项（日历/记忆）有主页可触达入口 |
| 5 | 日历 / 记忆 / 团队 | 补 wireframe（参考 v0.4），只移入口不砍功能 |
| 6 | AI | 标注 🆕 新增项；`?` 兼容全角；AI 推进 Context 预览保留 |
| 7 | 设置 | 4 tab + **隐私独立可见** |
| 8 | 复盘 | 不自动弹窗，改安静提示条 + 沿用防打扰机制 |
| 9 | 文档 | 合并为一份 `UX_DESIGN.md` |
| 10 | 实施 | 每步标注文件 / 测试影响 / 回滚 |

## 六、结论

- **方向对**：用户路径优先、行内展开、底部输入框、⌘K 分层——都是正确的现代生产力工具模式。
- **但有 4 个 P0**：两页模型自相矛盾、焦点/主动建议被删、日历/记忆/团队只剩命令、新手可发现性自相矛盾。**其中 P0-2 和 P0-3 是你两次提醒我的同一类错误（把功能藏没）第三次出现**——必须在定稿前修掉。
- **修正后可以实施**。建议按"先修文档（合并 + 补 wireframe）→ 再按修正后顺序逐步实施"推进。
