# DailyFlow UX 重新设计 · 用户路径版（v2）

> 配套文档：
> - `docs/UX_REVIEW_WIREFRAMES.md` —— v0.5 之前的版本（功能分门别类，已弃用）
> - `docs/UX_REDESIGN.md` —— 2 年前的 v1 版（today 是引力中心，已有部分相同结论）

## 核心原则（5 条）

1. **不展示功能，展示路径** —— 用户感受到的永远是"我正在做 X 这件事"，不是"这里有个 Y 功能"。
2. **能力按需浮现** —— 不点不开，不展开不见。需要时伸手就有，不需要时隐形。
3. **永远在主页** —— 切换的不是页面，是"展开/收起"。esc 永远回主页干净态。
4. **键盘 > 鼠标** —— 高频动作都给快捷键，低频动作用按钮。高手用户靠肌肉记忆，新手用户看按钮也能用。
5. **复杂操作在画布里** —— 涉及深度思考（事件/脑图/AI 推进）必须给独立空间，不能塞浮层。

## 5 条用户路径

```
P1  打开 → 看见今天 → 加几件事
P2  看到一条任务 → 想着手处理它
P3  觉得事情复杂 → 进画布深度思考
P4  想让 AI 帮点忙
P5  收尾：复盘、整理遗留、回顾
```

下面 5 张图对应 5 条路径，每张图**完整可走**，不省略细节。

## 关键设计决策（一句话版）

| 决策 | 为什么 |
|---|---|
| **主页只有清单 + 输入框** | Things / Linear / Apple Reminders 通用模式 |
| **任务行点开 → 行内展开** | 所有高级功能"按需浮现"，不点不见 |
| **底部固定输入框** | 永远在那里，不找 |
| **AI 是"帮你做"，不是"跟你聊"** | 给可一键操作的建议，不是聊天 |
| **Events 是"任务 → 转项目"的目的地** | 进得少但进得深，不抢主页注意力 |
| **AI 推进必须先弹 Context 预览** | 让"确认前 0 写入"对用户可见 |
| **`⌘K` 召唤所有"管理"动作** | 平时不显示，需要时伸手就有 |
| **esc 永远回主页干净态** | 永远可以"重置" |
| **Work / Life 在顶栏** | 离 Today 近，频繁切换 |
| **设置浮层 4 tab** | 按"用户旅程"组织，不按"代码模块" |
