# DailyFlow V2 路演承诺 vs 实际产品 · 差距分析与开发计划

> 生成时间：2026-08-20
> 比对基准：`docs/ROADSHOW_DECK_V2_CONTENT.md`（v7 16 页内容稿）
> 项目分支：`main` @ 011b397（v1.9.0）
> 文档目的：给 V2 路演稿的每一条产品主张找到代码对应，识别真正缺失的功能，**制定开发计划**

## 一句话结论

**V2 路演稿的 70% 产品主张有代码对应，30% 是"画大饼"或"含糊"。** 路演很精彩，但要把每一页承诺变成现实，需要补 7 个核心功能缺口；其中 4 个是产品必做（脑图节点类型 / AI 整理 / 主动提案 / 搜索排序），3 个是商业模式配套（向量索引 / 硬件 / 调度）。

## 二、缺失 / 半桶水功能清单（按"路演能否成立"的影响排序）

### P0 · 路演核心论点必做（4 项）

#### 缺口 1 · 脑图节点类型扩展（3 天）

**V2 承诺**：节点可以是疑问、资料、风险，不只是任务。

**现状**：`MindMapNodeKind = 'root' | 'branch' | 'tag' | 'task'` —— 4 种类型。

**需做**：
- 扩展 `MindMapNodeKind` 加入 `'question' | 'resource' | 'risk'`
- 让 `MindMapNode.tsx` 渲染不同视觉（图标 + 颜色：疑问蓝 / 资料灰 / 风险橙）
- 节点类型变更操作（菜单 / 工具栏）
- 模板里给出"项目"模板的 3 个示例节点

**影响**：Slide 04 立身页。评委问"为什么是脑图？"时直接展示。

#### 缺口 2 · AI 整理脑图节点成结构（5 天）

**V2 承诺**：AI 帮你把零散节点整理成结构（第 2 步）。

**现状**：完全手动。

**需做**：
- 服务端 `services/v2/agentService.ts` 新增 `organizeMindmap` 方法
- 入参：节点列表（文本 + 现有 kind） → 出参：分组（按主题 / 按优先级 / 按状态）+ 推荐连接
- 前端：脑图工具栏加"AI 整理"按钮；操作改为 Proposal 形式（用户确认后才落盘）
- 测试：3 个测试用例（10 节点 / 30 节点 / 50 节点）+ 1 个 e2e

**影响**：Slide 04 第 2 步。如果只能"手动整理"，亮点一沦为"画图工具"。

#### 缺口 3 · 主动提案（Proactive Proposal）机制（5 天）

**V2 承诺**：发现关联任务已逾期 5 天，主动问：要不要排进今天？

**现状**：`rollover.ts` 知道任务逾期，但只是被动等用户打开 Today 触发迁移。

**需做**：
- 新增 `services/v2/proactiveProposal.ts`：
  - 触发：用户打开 AI Chat / 应用启动 / Today 视图加载
  - 规则：memory 中提到的会议 / 承诺 → 关联 task → 逾期 > 5 天 → 生成 Proposal
  - Proposal 类型：建议"今天执行" / 建议"重新分组" / 建议"标记完成"
- UI：Today 顶部加"Agent 建议"卡片（1 张或折叠）
- Proposal 第一条放在用户最关心的位置（视觉提示）

**影响**：Slide 06 第 3 步。是"用得越久越懂你"能否成立的判定性瞬间。

#### 缺口 4 · 3 层搜索排序（结构化 → 元数据 → 全文）（3 天）

**V2 承诺**：找的时候先结构化关联，再元数据，再全文。

**现状**：`memoryService.search` 是单个函数，3 层排序未明确。

**需做**：
- 重写 `memoryService.search` 为 3 个有序步骤：
  1. **结构化关联**：先查 `linkedTaskIds` / `linkedNoteIds` / `linkedMindMapNodeId` 直接命中
  2. **元数据**：title / tag / date / status / owner 完全匹配加权
  3. **全文**：FTS5 / LIKE 模糊匹配
- 给每个 hit 标 `matchTier: 'structured' | 'metadata' | 'fulltext'`
- `MemoryView.tsx` 排序时高亮 structured 命中
- 测试：3 个测试用例（结构化 / 元数据 / 全文）

**影响**：Slide 06 第 1 步。直接决定"用了一年问得出来"的真实性。

### P1 · 必做 · 路演细节刷亮（3 项）

#### 缺口 5 · 日报 + 日复盘（4 天）

**V2 承诺**：日报周报自动生成，做完了什么、什么被推迟，全部存回文件。

**现状**：只有 `weekly_report` skill，没有日报。

**需做**：
- 新增 `services/v2/dailyReport.ts`：
  - 输入：今日完成任务 + 逾期任务 + 推迟任务
  - 输出：Markdown 报告，写入 `Journal/2026-08-20.md`
- `builtInSkills.ts` 加入 `daily_report` skill
- Today 视图加"今日复盘"按钮（一键生成）
- 归档=自动日报（每晚 22:00 触发）

**影响**：Slide 03 第 4 步"复盘"必须有。

#### 缺口 6 · 任务完成后回写脑图（3 天）

**V2 承诺**：任务进入 Today 执行，结果自动回流——思考过程永远留在原地。

**现状**：任务完成后只是改状态，没有回写到脑图节点。

**需做**：
- `taskEventConversion.ts` 新增 `taskCompletionMirror`：
  - 任务完成 → 找关联节点（通过 `taskId`）
  - 节点状态：未完成 → 已完成（视觉变化）
  - 节点文本附加："完成时间 + 草稿结果摘要"
- 沉淀到脑图历史（不是删掉）
- 测试：3 个用例

**影响**：Slide 04 收束句"思考过程永远留在原地"成立。

#### 缺口 7 · 本地 Whisper 转写（4 天）

**V2 承诺**：会议录音本地转写（Slide 03）。

**现状**：默认走 OpenAI Whisper API（音频上传到云端）。

**需做**：
- 集成 `whisper-node` 或 `whisper.cpp`（Tauri 2 二进制）
- 设置面板：转写后端选择（OpenAI / 本地 Whisper）
- 本地 Whisper 启动延迟 < 5s（首次 30s）
- 测试：1h 音频转写 + 准确率检查

**影响**：Slide 05 "0 字节上传"承诺的诚实性。如果默认上传，"主权 AI"立刻被打穿。

### P2 · 商业模式配套（3 项）

#### 缺口 8 · 向量索引（可选加速）（5 天）

**V2 承诺**：本地全文检索永远免费，向量索引是可选项。

**现状**：无 vector index 代码。

**需做**：
- `services/v2/vectorIndex.ts`：基于 `lancedb` 或 `sqlite-vss` 的轻量向量索引
- 索引内容：笔记 / 任务 / 会议 摘要
- 触发：每 100 个新文件 / 手动
- UI：模型中心加入"向量索引"开关

**影响**：Slide 12 商业模式"记忆规模变大后"承诺成立。

#### 缺口 9 · 0 字节上传技术验证（1 天）

**承诺**：0 字节上传。

**现状**：本地 Whisper 缺失（缺口 7）+ AI Chat 走云端（15+ 模型都要）。

**需做**：
- 审计：把所有 HTTP 上传路径列出来
- 区分"用户授权上传"（如 AI 调用必传 prompt）和"框架偷偷上传"（不应有）
- README 写明"AI 调用 = 直连厂商 API，无中间服务器"

**影响**：Slide 05 / 12 商业模式的诚实性。

#### 缺口 10 · Skill 市场雏形（5 天）

**承诺**：开源 Agent 市场，第三方开发者发布技能，市场交易分成。

**现状**：Skill 概念存在，无市场 / 交易。

**需做**：
- 不用做完整电商，但做"Skill 注册中心"：
  - GitHub `dailyflow-skills` 仓库托管 Skill manifest
  - 在 `ModelLibrary` 加"导入社区 Skill"按钮
  - 评级 + 评论先不做

**影响**：Slide 12 第 5 类的一个"已开始的证据"。

## 五、风险与提醒

1. **缺口 2（AI 整理脑图）难度最高**——AI 输出的"结构"很难让用户满意，需要：(a) 3 个 fallback 策略（按主题 / 按优先级 / 按时间），(b) 永远给"撤销"按钮，(c) 第一次仅给推荐，让用户确认。
2. **缺口 3（主动提案）容易被觉得"太烦"**——必须加：(a) 全局开关，(b) 静默时段（深夜不提），(c) 每周最多 3 次主动提案。
3. **缺口 4（3 层搜索）排序策略需要产品定**——不是技术问题，是产品决策。结构化关联的 hit 数应该占多少？需要先做产品决定，再写代码。
4. **缺口 7（本地 Whisper）首次启动延迟**——whisper.cpp 启动 5-10 秒是正常的，需要缓存模型 + 进度条。
5. **缺口 1（节点类型）会破环现有节点**——需要数据迁移：4 种 → 7 种，旧节点保持 `branch` 行为不变。
6. **路演现场"承诺过头"风险**——演示要严格控制：演示主动提案只演示 1 个场景，不要演示 3 个。
7. **V2 内容稿与现状对照后，**还有 14 个 gap 类别（详见文档表格），但大部分是"半桶水"或"承诺但未实现"，商业务必不要承诺过头。

## 七、关键判断
