## 1. 产品一句话

DailyFlow 是一款面向复杂日程和长期任务的本地优先日程管理软件：用 Markdown 作为主数据，用 Web 界面提升操作效率，用自动迁移、项目追踪和思维导图减少每天重复整理任务的负担。

## 2. 背景与问题

当前用户使用 Obsidian 中的 Markdown 日记管理每日事项，典型流程是每天复制前一天文件、手动保留未完成任务、手动整理长期事项。这个流程灵活，但在任务量大、任务跨度长、附件多、项目层级复杂时，会产生明显摩擦。

### 主要痛点

| 痛点 | 具体表现 | 影响 |
|---|---|---|
| 每天复制成本高 | 未完成任务需要从昨天手动复制到今天 | 每天产生机械劳动，容易漏项 |
| 长期任务漂浮 | 多个月的大任务一直散落在每日文件里 | 难以判断进度、阻塞点和下一步 |
| 任务结构不稳定 | 有些任务有截止时间，有些没有；有些有附件，有些没有 | 工具难以统一管理 |
| 拆解过程割裂 | 复杂事项需要先想清楚路径，再手动写成小任务 | 从思考到执行之间断层明显 |
| 任务缺少思考空间 | 一个任务背后有零散想法、资料、风险和疑问，但任务卡片只能承载一行文字 | 复杂事项推进时反复重新理解上下文 |
| AI 没有进入事项旅程 | AI 可以总结内容，但还没有围绕单个任务持续整理、规划、复盘 | AI 价值停留在文本生成，没有变成执行辅助 |
| 数据不想被锁定 | 商业 Todo 工具难迁移，隐私和备份不可控 | 长期使用风险高 |

## 3. 产品目标

### 3.1 核心目标

1. 降低每日维护成本：未完成任务自动迁移，今天的文件自动生成。
2. 保留 Markdown 自由度：用户仍可在 Obsidian/任意编辑器中直接编辑文件。
3. 管理长期复杂项目：项目有独立视图、子任务、进度、日志和附件。
4. 给复杂事项提供思考工作台：零散想法、AI brief、完成路径、子任务、脑图和复盘集中在一个任务空间。
5. 让思考自然变成任务：思维导图节点可转成任务并回链。
6. 适合开源和私有化部署：轻依赖、可 Docker 部署、可 GitHub 同步。

### 3.2 非目标

- 不做企业级协同审批系统。
- 不在 MVP 中做复杂排班、会议室、多人日历邀请。
- 不把 SQLite 设计为唯一主数据库；Markdown 必须是主数据。
- 不强依赖云服务；任何云同步都应可关闭。
- 不在早期引入过重 AI 自动规划，避免错误规划影响日程可信度。

## 4. 目标用户与场景

### 4.1 用户画像

| 用户 | 特征 | 关键需求 |
|---|---|---|
| 创业者/管理者 | 公司、融资、客户、个人事项并行 | 快速看到今天重点和长期项目进度 |
| Obsidian 用户 | 熟悉 Markdown 和双链 | 不破坏现有文件结构，增强自动化 |
| 独立开发者 | 项目多、需求多、切换频繁 | 任务能从想法拆解到执行 |
| 投研/咨询/BD | 附件和链接多、事项跨周期 | 任务、资料、记录要关联在一起 |

### 4.2 高频场景

**场景 A：早上打开 DailyFlow**

1. 系统检查今天是否已有日记文件。
2. 如果没有，从昨天提取未完成任务，生成今天文件。
3. 用户看到按分类归档的今日任务，包括从昨天滚动来的任务。
4. 用户补充今天的新任务，并为部分任务加截止日期或项目关联。

**场景 B：某个任务今天做不完**

1. 用户保持任务未完成。
2. 次日系统自动把它迁移到新日记。
3. 昨天文件中记录 `↗ migrated:2026-05-04`，方便追溯。
4. 任务保留子任务、说明、附件和链接。

**场景 C：长期项目持续推进**

1. 用户把「投资搞定」设为项目。
2. 项目文件中维护子任务、每日记录、附件和相关链接。
3. 每天日视图只显示一个项目入口或当天计划推进的子任务。
4. 用户每天手动记录推进情况，系统自动更新时间线和完成率。

**场景 D：用思维导图拆解复杂事项**

1. 用户在项目中打开思维导图。
2. 围绕中心任务拆出分支、依赖和下一步行动。
3. 选中可执行节点，点击「生成任务」。
4. 系统把节点写入项目文件或某一天的日记文件，并保留 mindmap 回链。

## 6. 核心功能设计

### 6.1 自动迁移

**用户价值：** 解决每天复制 Markdown 文件和漏任务的问题。

**规则：**

- 只迁移未完成任务：`- [ ]`。
- 已完成任务保留在原日期：`- [x]`。
- 支持任务块迁移：任务的缩进子项、引用说明、附件、标签一并迁移。
- 支持跳过迁移：任务包含 `#no-rollover` 时不自动迁移。
- 支持固定日期：任务包含 `#scheduled:YYYY-MM-DD` 时只在指定日期出现。
- 支持截止提醒：任务包含 `#deadline:YYYY-MM-DD` 时在临期区展示。
- 迁移后给原任务追加来源标记，避免重复迁移。

**示例：**

```markdown
- [ ] 完成 secondplanet 上线 #deadline:2026-05-10 #priority:high
  > 说明：完成前端部署、域名配置和基本监控。
  > 链接：https://github.com/example/secondplanet
  - [ ] 前端构建
  - [ ] 服务器部署
  - [ ] 域名配置
```

### 6.2 长期项目追踪

**用户价值：** 大任务不再散落在每天的日记里，而是沉淀为一个可持续更新的项目对象。

**项目包含：**

- 基础信息：名称、状态、分类、开始日期、截止日期。
- 子任务树：可嵌套、多层级、可标记完成。
- 每日记录：按日期记录推进、阻塞、决策。
- 关联资料：文件附件、URL、Obsidian 链接。
- 今日入口：可把项目或某个子任务 pin 到某一天。


### 6.3 思考工作台

**用户价值：** 复杂事项不必先被压缩成一行 task。用户可以先创建一个独立思考空间，把目标、问题、资料、脑暴和判断放进去，再由 AI 帮忙整理路径，并从中生成今天或未来要执行的小任务。

**定位：** Thinking Workspace 是一等对象，不依附于 task。它可以从大目标、零散想法、项目、note 或 task 创建；task 只是它产出的行动项之一。

**核心模块：**

- Intent：这个空间想解决什么问题，或要达成什么目标。
- Scratchpad：收集零散想法、链接、聊天结论、疑问。
- Brief：AI 把零散输入整理成目标、背景、成功标准和缺失信息。
- Journey / Plan：AI 规划完成路径、阶段、依赖、风险和下一步行动。
- Tasks：从 Journey 生成可执行 checkbox，用户确认后投放到 Today、未来日期或项目。
- Mind Map：把目标、路径、风险、资料、问题和决策可视化。
- Timeline：记录每天推进、阻塞、决策和 AI 复盘建议。

**核心交互：**

1. 用户从 Cmd+K、项目、note 或 task 创建思考空间。
2. 用户把零散想法写进 Scratchpad，或关联已有 notes / files / links。
3. 点击「帮我理清这件事」生成 Brief。
4. 点击「规划推进路径」生成 Journey。
5. 点击「生成下一步任务」进入 preview，确认后投放到 Today、未来日期或项目。
6. 点击「生成脑图」获得 Mermaid mindmap 或可编辑脑图。
7. 推进过程中，AI 根据 Timeline 和任务完成情况复盘并调整下一步。

**原则：** AI 输出必须先进入 preview，不自动覆盖用户内容；workspace 不会因为某个 task 完成就自动结束。

详见：`docs/THINKING_WORKSPACE.md`。

### 6.4 思维导图集成

**用户价值：** 先发散思考，再把明确行动转成任务。

**核心交互：**

- 中心节点是项目或任务。
- 普通节点用于想法、路径、风险、资源。
- 可执行节点标记为 `task`，可批量生成 Markdown 子任务。
- 任务与节点双向关联：任务中记录 `mindmap:<id>#node:<id>`。
- 支持导出为 Markdown outline，保证数据不被画布格式锁定。

### 6.5 附件和链接管理

**用户价值：** 任务相关材料不会散落在微信、浏览器、网盘和笔记里。

**支持类型：**

- 本地文件：PDF、Word、Excel、图片等。
- URL：网页、GitHub、飞书、网盘链接等。
- Markdown 引用：Obsidian wikilink、项目文件、会议纪要。
- 说明文字：短说明用 blockquote，长说明用独立 note。

### 6.6 Git 同步

**用户价值：** 保持本地优先，同时获得版本历史、多设备同步和备份。

**原则：**

- 默认不自动 push，先本地 commit，用户可设置自动 push。
- 每次迁移、批量编辑、项目更新都形成可读 commit message。
- 发现冲突时不自动覆盖，展示冲突文件和解决建议。
- GitHub 是同步方案之一，不是产品的强制依赖。

## 9. MVP 范围

### P0 必须完成

- 配置一个本地日记根目录。
- 解析指定日期的 Markdown 日记。
- 展示今日任务，支持按分类折叠。
- 勾选完成任务并写回 Markdown。
- 手动触发「生成明天」或「迁移到今天」。
- 自动迁移未完成任务，保留子任务和说明。
- SQLite 建索引，用于快速搜索和列表展示。

### P1 下一阶段

- 思考工作台：复杂事项的 Scratchpad、AI Brief、Plan、Subtasks、Timeline。
- AI 规划动作：整理思路、规划路径、生成子任务、生成脑图、复盘进度。
- 项目文件管理与项目视图。
- Git commit / push / pull 状态面板。
- 思维导图编辑器与节点转任务。
- 附件和链接面板。
- 截止日期和长期未更新提醒。

### P2 未来增强

- AI 辅助跨项目复盘和长期目标调整，但必须由用户确认。
- 移动端 PWA。
- 多仓库/多 vault 管理。
- 插件系统：番茄钟、日历订阅、导入器等。

## 10. 设计风格

DailyFlow 的视觉方向调整为 **Editorial Productivity OS**，重点参考 dinq.me 的黑白网格、编辑感大标题、胶囊命令框、粗线框卡片和少量高饱和色块。目标不是做传统 SaaS Dashboard，而是做一个「像杂志封面一样有记忆点、像命令中心一样高效」的日程产品。

### 10.1 视觉关键词

- **Black & White First**：白底、黑字、黑色 CTA，整体干净有力。
- **Editorial Hero**：landing、空状态和引导页使用超大 serif 标题，例如 `One Day, All Tasks Flow Forward.`
- **Grid Canvas**：淡灰网格作为背景，暗示日程、坐标、计划和结构。
- **Command Pill**：核心操作用胶囊命令框承载，例如 `dailyflow / today / rollover`。
- **Floating Task Cards**：任务、项目、附件可以像卡片一样漂浮、倾斜、关联，但日常列表保持克制。
- **Monochrome + Sparks**：主体黑白，亮蓝、薄荷绿、淡紫、浅粉只用于迁移成功、已完成、思维导图和逾期风险。

### 10.2 产品界面转译

| DINQ 风格元素 | DailyFlow 应用方式 |
|---|---|
| `One Card, All About Me` 的大标题 | `One Day, All Tasks Flow Forward.` / `Tomorrow is already drafted.` |
| 黑色 Claim CTA | 黑色 `Rollover`、`Commit`、`Create Today` 主按钮 |
| `dinq.me/yourname` 输入框 | `dailyflow / 2026-05-03 / migrate` 命令栏 |
| 漂浮 profile 卡片 | 漂浮任务片、项目进度片、附件片 |
| Tab 模块 | Today / Projects / Mindmap 三段切换 |
| FAQ 大折叠列表 | 设置页、帮助页、迁移规则说明 |
| 鲜蓝 CTA section | 首次设置、迁移成功、开源贡献引导 |

### 10.3 体验边界

- 日常任务流不能过度装饰，优先保证可读性和效率。
- 大标题和漂浮卡片主要用于首页、空状态、项目概览和营销页。
- 任何批量动作都必须先预览 diff，再确认执行。
- 不复制 DINQ 的品牌资产，只借鉴视觉语言和交互气质。

详见：[DINQ 风格转译](./docs/DESIGN_REFERENCE_DINQ.md) 与 [UI 设计规范](./docs/UI_DESIGN.md)。

## 11. 成功指标

| 指标 | 目标 |
|---|---|
| 每日创建日记耗时 | 从 10-15 分钟降到 1 分钟内 |
| 未完成任务漏迁移 | 接近 0 |
| 长期项目周更新率 | 每个活跃项目每周至少 1 次记录 |
| Markdown 可迁移性 | 不依赖 App 也能阅读和编辑 |
| 私有化部署成本 | 30 分钟内完成 Docker 部署 |

## 12. 待确认问题

1. 当前 Obsidian 日记中有哪些固定标题结构需要兼容？例如「个人事项」「公司事项」「已完成」。
2. 任务被迁移多次时，是保留完整迁移链，还是只保留最新迁移日期？
3. 项目任务出现在日视图中时，是显示项目入口，还是显示当天手动 pin 的子任务？
4. Git 同步默认是否自动 push，还是只自动 commit？
5. 思维导图数据格式优先选择 JSON Canvas、React Flow JSON，还是 Markdown outline？
