# Skill: 内容写作

> 读取选题分析报告，撰写一篇完整的技术文章。

## 触发条件

当 `$OUT/topic.md` 已生成时触发（`$OUT` 为主编排创建的当前输出目录）。

## 执行步骤

1. **读取选题**：从 `$OUT/topic.md` 提取以下信息
   - 标题、目标读者、核心价值
   - 文章结构建议（作为大纲基础）

2. **生成大纲**：基于结构建议，细化每段的小节
   - 每段设 2-3 个小节
   - 标注代码示例的位置
   - 标注配图位置，使用 `[IMAGE: 图片描述]` 格式

3. **逐段撰写**
   - 开头：用真实场景引入，让读者产生共鸣
   - 正文：技术内容配合代码示例，用类比解释复杂概念
   - 过渡：段落之间自然衔接
   - 结尾：给出行动建议和延伸阅读方向

4. **质量自检**（写完后自动检查）
   - [ ] 总字数在 2000-4000 之间
   - [ ] 代码示例语法正确、可运行
   - [ ] 逻辑连贯，没有跳跃
   - [ ] `[IMAGE: ...]` 标记数量在 2-5 处
   - [ ] 不合格则自动修改后重新检查

## 输出

写入 `$OUT/article.md`（标准 Markdown 格式）

## 写作风格

- 技术准确但不晦涩，用类比解释复杂概念
- 段落简短（每段 ≤ 5 句），语气像资深同事分享经验
- 代码示例要完整可运行，不要省略关键部分
- `[IMAGE: ...]` 标记的描述要具体，方便配图 Skill 理解需要什么图

## IMAGE 标记示例

```markdown
[IMAGE: Rust 异步 vs 同步模型对比图，左侧显示线程阻塞，右侧显示异步任务复用]
```

这不是最终内容，而是给下游配图 Skill 的"指令"——告诉它在哪里配什么图。
